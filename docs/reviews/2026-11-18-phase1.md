### H1. A qualified or aliased `Call` type hides the whole contract from the lint
- **Sequence:** a production contract `Settlane` declares `uses (ctx: Ctx, call: mut std::evm::Call)` (or `use std::evm::Call as Pay` and `call: mut Pay`). A non-payout arm `Approve { to } uses (mut call)` calls `send_value`.
- **Expected:** `E-CALL`. **Actual (at `85731a7`):** `settlane-lint: ok`. The type was compared as the raw string `std::evm::Call` (or `Pay`), so `value_names` was empty and no rule ran for the contract. The runtime test moved 1 ETH. The files are `fe fmt`-clean.
- **Repro:** `experiments/review/b1_qualified_type.fe`, `b2_alias.fe`.
- **Fix:** effect types are normalised (last path segment), and `use .. as` / `type .. =` aliases in the file are resolved. In the production ingot, contract-level effect types must be on an allowlist (`Ctx`, `Log`, and the privileged types), so an alias the lint cannot resolve, such as one defined in another file, fails closed (`E-EFFECT`). `E-SHADOW` rejects a production definition or alias named like a std effect.
- **Regression:** fixtures `bad_call_qualified_type.fe`, `bad_call_import_alias.fe`, `bad_call_alias_other_file.fe`, `bad_shadow_std_effect_name.fe`; three normalisation unit checks; negative controls `qualified-call-type-in-production`, `call-import-alias-in-production`; `experiments/review/run.sh`.

### H2. A lowercase arm name merges into the previous arm and inherits its permission
- **Sequence:** `msg SettleMsg { Claim {..}, approve {..} }` (Fe accepts lowercase variants). In `recv`, `approve { to } uses (mut call)` follows `Claim`.
- **Expected:** `E-CALL` for `SettleMsg::approve`. **Actual:** `ok`, and 1 ETH moved. `arms_in` started a new arm only on `[A-Z]`, so `approve` became part of `Claim`'s text.
- **Repro:** `experiments/review/b3_lowercase.fe`.
- **Fix:** any identifier starts an arm. As a fail-closed backstop, one parsed arm holding more than one `uses (` header is `E-PARSE` (this also catches an arm started on the closing line of another).
- **Regression:** fixtures `bad_lowercase_arm.fe`, `bad_merged_arms_one_line.fe`; negative control `lowercase-arm-in-production`.

### H3. Raw storage is not covered
- **Sequence:** `pub contract Settlane uses (raw: mut RawStorage)`, a non-payout arm `Poke { slot, v } uses (mut raw) { unsafe { raw.sstore(slot: slot, value: v) } }`.
- **Expected:** rejected. **Actual:** `ok`, and the test overwrote a compiler-allocated field (slot 0). In Settlane this could mark a milestone `Approved` or move a deadline, then a legitimate `Claim` pays. I11's balance check would not notice.
- **Repro:** `experiments/review/r2_rawstorage.fe`.
- **Fix:** `RawStorage` and `RawOps` are privileged `value_types` in `scripts/lint-policy.json`. `unsafe` is forbidden anywhere in the production ingot (`E-UNSAFE`).
- **Regression:** fixture `bad_raw_storage.fe` (expects `E-CALL` and `E-UNSAFE`); negative control `raw-storage-in-production`.

### H4. `C-CLOCK` bypasses
- **Sequence (a):** inside an arm, `let ctx = Fake { t }` where `Fake` has `fn timestamp(self) -> Timestamp`, then the exact literal `Clock { now: ctx.timestamp() }`. **(b):** `type Tick = Clock`, then `Tick { now: t }`. Variant: a helper `uses (ctx: Fake)` provided by `with (Fake = Fake { t })`.
- **Expected:** `C-CLOCK`. **Actual:** `ok`. Both runtime tests showed `IsOpen` answering for a caller-chosen time in a contract named `Settlane`. `C-ABI` checks only function names, so it misses this too. A Clock constructor (`impl Clock { fn at(t) -> Self { Self { now: t } } }`) was caught only because `impl Clock {` happened to match the literal regex.
- **Repro:** `experiments/review/c2_clock_shadow.fe`, `c3_clock_alias.fe`, `c1_clock_ctor.fe`.
- **Fix:** in the production ingot, `C-CLOCK` also rejects any alias of Clock, any `impl` block with a body on Clock, any `uses` item named `ctx` whose type is not `Ctx`, and any `ctx` outside a `uses (..)` list that is not `ctx.method(..)`. `C-ABI` also rejects time-like *input* names on state-changing functions.
- **Limit:** this is still a textual check. The PC runtime test (call `SetTime` on `Settlane`, expect a revert or an absent selector) remains required in Phase 2.
- **Regression:** fixtures `bad_clock_ctx_shadowed.fe`, `bad_clock_ctx_lookalike_effect.fe`, `bad_clock_type_alias.fe`, `bad_clock_impl_constructor.fe`; ABI unit check; negative controls `shadowed-ctx-clock-in-production`, `clock-type-alias-in-production`.

### M1. `C-ARTIFACT` looked only at `*.abi.json`, and `fe build` never clears `out/`
- **Sequence:** `fe build`, then `fe build ingots/settlane-dev --emit bytecode,runtime-bytecode --out-dir out`.
- **Expected:** `C-ARTIFACT` (a test contract's bytecode is in the production output). **Actual:** `ok`. `out/` held `Actor.bin` and `Actor.runtime.bin`. A marker file placed in `out/` survived a rebuild.
- **Fix:** every file in `out/` must be a known artifact type of a deployable contract; directories and unknown files fail. Each deployable contract needs `.bin`, `.runtime.bin` and `.abi.json`, each newer than the newest production source (stale artifacts fail). CI runs `rm -rf out` before `fe build`.
- **Regression:** six unit checks in the lint self-test; `experiments/review/run.sh` repeats the real build shape and a clean-build control.

### M2. `#[test(should_revert)]` passes on any revert
- **Sequence:** in `withdraw_before_unlock_reverts`, give the `Deposit` setup call `gas: 1`.
- **Expected:** the test fails (it never reached `Withdraw`). **Actual:** `PASS`.
- **Fix:** the test now runs its setup with `evm.call` (which must succeed), checks a positive control (the deposit landed), asserts `!try_call(Withdraw).success()`, and checks that balances are unchanged. New lint rule `T-REVERT` rejects a `should_revert` without a `panic = ..` code in either ingot.
- **Regression:** with the setup starved, the test now fails (negative control `starved-setup-in-negative-test`). Fixtures `bad_bare_should_revert.fe`, `ok_should_revert_with_panic.fe`; negative control `bare-should-revert-test`.

### S-1. `Reject` does not bind evidence (approved, D-015)
- **Sequence (spec at `85731a7`):** the provider submits `e1`. The verifier reviews `e1` and sends `Reject`. Before it lands, the provider resubmits a fix `e2` shortly before `deliver_by`. `Reject` lands and rejects `e2`, which the verifier never saw. Delivery is now closed, so the milestone is `Funded ∧ ¬delivery_open`, which is expired, and the client refunds.
- **Expected:** a rejection applies only to the evidence reviewed. **Actual (spec):** wrong settlement under an honest verifier. Likelihood is low (needs a race near the deadline).
- **Decision:** T4 becomes `Reject(e)` with guard `e == stored evidence`, mirroring T3. Not runtime-tested yet, because the contract does not exist. Phase 3 must test it.

### S-2. Shell divergence (adopted, D-016)
As planned, the deadline-crossing tests would exercise `SettlaneTestClock`'s copy of each arm, not `Settlane`'s. `Settlane` can never reach a successful `Refund` in frozen time, because creation requires `deliver_by > now`. `experiments/review/s1_shared_arm.fe` shows that in Fe 26.6.0 a whole handler (deadline check, storage, transfer) can be one shared `pub fn` taking contract fields as effects. Each shell's arm is then only `with (Clock = ..) { handler(..) }`. The lint accepts this shape (`ok_shared_handler.fe`).

### S-3. Lost keys lock funds (documented)
`Approved` never expires and only the provider can claim it. Expired milestones can only be refunded by the client. A lost key, or a client contract that cannot issue `Refund`, locks those funds permanently. This is by design (no admin and no sweep), now stated in `docs/SECURITY.md`.

### S-4. Unset keys read as the first enum variant (adopted, D-017)
E3 shows an unset key reads as the first variant. If `MilestoneState` did not start with `None`, unused slots and unknown ids would read as `Funded` with `deliver_by == 0`, which counts as expired, so a 0-wei `Refund` would succeed and change the state. `None` must be the first variant, with tests on an unused slot and an unknown id.

## Verified, no issue
- **u8 at the ABI boundary:** 300 is rejected at decode, while the same call with 2 succeeds (`experiments/review/u1_u8_abi.fe`). This closes an FE_NOTES open item.
- **Guards:** `Submit`/`Refund(Funded)` and `Approve`·`Reject`/`Refund(Submitted)` are disjoint at every `now` (I10) as specified.
- **Double payment:** the spec writes state before the send, and `Paid`/`Refunded` are terminal (I3, I4), to be tested in Phase 4.
- **`scripts/check_tests.py`:** no false-green parse path found.

## Unresolved and untested

- The dev tests' copy of production code cannot be proven byte-identical to the shipped artifact (E10).
- The lint is still textual. Shapes not tried: generics, macros, multi-contract files, and effects re-provided through `with` in production. Codex R-001 is still needed.
- `C-CLOCK` is a textual guard. The runtime PC test does not exist yet.
- `#[event]` with `Wei` and `u8` fields is unverified.
