**Source.** The owner ran the R-002 review with Codex and relayed five findings in the request
that started this fix round. No findings file from the reviewer is in the repository, so the
text of the findings below is the owner's relay, not a quotation. Each one was **reproduced
against Fe 26.6.0 before it was fixed**, and each fix has a regression test and a CI negative
control. Nothing here claims more than what was run.

## Found while fixing (not in the review)
- `arms_in` treated a wrapped `uses (..)` line (what `fe fmt` produces) as a new arm named `uses`. It came from the earlier H2 fix. It was harmless in Phase 2A, but a wrapped payout arm in Phase 3 would have been flagged as a non-payout arm. Fixed, with fixtures for both a wrapped payout arm (must pass) and a wrapped non-payout arm (must fail).
- My new selector regex flagged every `sol(..)` selector because `\s*` backtracks past a negative lookahead. Caught by running the lint on the real tree.
- The raw-selector wide-`n` test could not stay in the production ingot under the new rule. It moved to the dev ingot, which is where test machinery belongs.
- My first expectations for two pure tests and one event sequence were wrong (I reused a fixture with the wrong id, and set `n = 2` without clearing slot 2). The checkers reported them, and the code was right.
